Ola’s MCP Tool Result Research

How crewAI handles MCP tool results

which mcp tool result fields are used and how (clients)

Notes from reading the crewAI source (clones/crewai, checked out at commit d7dfa0ef5ade793bd48ff7357c6eb45a45294371 (d7dfa0e), read on 2026-11-14). File references are relative to lib/ unless they name uv.lock or an SDK file. SDK references are to the mcp 1.30.0 wheel, which crewai/pyproject.toml requires as "mcp>=1.30.0,<2" and uv.lock resolves to version = "1.30.0". The mcp extra in crewai-tools/pyproject.toml adds "mcpadapt>=0.1.9", locked at 0.1.19 or 0.1.20 depending on the Python version.

Entry: three SDK client paths, all typed as mcp.types.CallToolResult

crewai/src/crewai/mcp/tool_resolver.py MCPToolResolver.resolve routes an agent’s mcps list. A string starting with https:// goes to _resolve_external, which builds MCPToolWrapper objects. Any other string is an AMP slug, and _resolve_amp fetches its config and passes it to _resolve_native. A config object goes to _resolve_native, which builds MCPNativeTool objects. The native path calls MCPClient._call_tool_impl in crewai/src/crewai/mcp/client.py, which awaits self.session.call_tool(tool_name, arguments) on an SDK ClientSession. The HTTPS path calls session.call_tool(self.original_tool_name, kwargs) inside MCPToolWrapper._execute_tool in crewai/src/crewai/tools/mcp_tool_wrapper.py. Both open a new session for every call: MCPNativeTool._run_async calls self._client_factory() and disconnects in finally, and _execute_tool enters streamablehttp_client and ClientSession per call. The third path is MCPServerAdapter in crewai-tools/src/crewai_tools/adapters/mcp_adapter.py, which hands tool construction to mcpadapt.core.MCPAdapt with a CrewAIToolAdapter; mcpadapt keeps one session and calls session.call_tool(name, arguments) in _sync_call_tool (mcpadapt/core.py). The SDK type is CallToolResult in mcp/types.py, with content: list[ContentBlock], structuredContent: dict[str, Any] | None = None, isError: bool = False, and meta (alias _meta) from Result. The identifier structuredContent appears in no crewAI source file under lib/. structuredContent survives SDK parsing on all three paths as a field of the CallToolResult that crewAI receives. content has no default, so a result without the content key fails result_type.model_validate in BaseSession.send_request (mcp/shared/session.py) with a pydantic validation error, and no crewAI code receives a result.

Model path: every block as text, with a repr of the whole result when content is empty

MCPClient._call_tool_impl decides the native path. It reads isError, then under if hasattr(result, "content") and result.content: returns content_blocks_to_text(result.content) (crewai/src/crewai/mcp/content.py), which joins every block with newlines. When content is empty it falls through to return _MCPToolResult(str(result), is_error). MCPNativeTool._extract_content (crewai/src/crewai/tools/mcp_native_tool.py) receives that string and returns it unchanged. MCPToolWrapper._execute_tool has the same shape: if result.content: returns content_blocks_to_text(result.content), and ends with return str(result). str() of the pydantic model prints every field, so with empty content the model reads meta=None content=[] structuredContent={...} isError=False. With both fields present, these two paths send every block, and structuredContent is dropped. Text blocks and embedded text resources keep their text. A non-text block becomes a typed placeholder, so an image or audio block reaches the model as [image: image/png] with no base64, an embedded blob as [resource: <uri>], and a resource link as [resource_link: <uri>]. No path compares the text with structuredContent, so when the text mirrors the JSON the model reads it once, as the text. The structuredContent value inside the str(result) string is the Python repr of a dict, with single quotes and True, False and None, so it is not JSON. No path substitutes a placeholder for an empty result: empty content gives the repr above, and a single empty text block gives an empty string.

The adapter path is CrewAIMCPTool._run inside CrewAIToolAdapter.adapt. It returns first_content.text or str(first_content) when len(result.content) == 1. Otherwise it returns str([content.text for content in result.content if isinstance(content, TextContent)]), a Python list literal of every text block. Empty content yields the string []. Non-text blocks are dropped when there is more than one block. structuredContent never reaches the model on this path. A single non-text block reaches the model as str(first_content) (crewai-tools/src/crewai_tools/adapters/mcp_adapter.py), the pydantic repr of the block, which for an image or audio block includes the base64 data field and the annotations field.

No path reads annotations.audience. content_blocks_to_text, CrewAIMCPTool._run and MergeAgentHandlerTool._run never read a block’s annotations, so a text block marked audience: ["user"] reaches the model like any other. Under lib/, audience appears only in OAuth and OIDC code (crewai/src/crewai/a2a/auth/server_schemes.py, crewai-core/src/crewai_core/auth/, crewai-core/src/crewai_core/settings.py, cli/src/crewai_cli/enterprise/main.py) and in catalog text in crewai-core/src/crewai_core/platform_catalog.py and crewai-core/src/crewai_core/platform_apps.py. The SDK Annotations model in mcp/types.py declares audience: list[Role] | None = None.

isError is carried only on the native path. MCPNativeTool._run_async returns a ToolFailure with reason=ToolFailureReason.MCP_ERROR when tool_result.is_error, and format_native_tool_output_for_agent (crewai/src/crewai/utilities/agent_utils.py) renders it with as_agent_message(), which is the same extracted string. The HTTPS wrapper and the adapter never read isError, so an error result reaches the model as an ordinary result.

outputSchema: dropped at discovery, validated by the SDK

No crewAI path keeps outputSchema. MCPClient._list_tools_impl rebuilds each tool as a dict with four keys, name, original_name, description and inputSchema. MCPToolResolver._discover_mcp_tools stores only description and args_schema per tool. CrewAIToolAdapter.adapt reads mcp_tool.name, mcp_tool.description and mcp_tool.inputSchema.

The SDK validates on all three paths. ClientSession.call_tool in mcp/client/session.py runs _validate_tool_result when not result.isError. That method re-lists tools when the name is not in _tool_output_schemas, which happens on every native and HTTPS call because each uses a fresh session. It raises RuntimeError(f"Tool {name} has an output schema but did not return structured content") or RuntimeError(f"Invalid structured content returned by tool {name}: {e}"). The HTTPS wrapper sends the name produced by sanitize_tool_name (crewai/src/crewai/utilities/string_utils.py), which lowercases and splits camelCase. When sanitizing changes the name, the SDK does not find it after re-listing, logs Tool {name} not listed by server, and skips validation.

What the model sees on a validation failure differs by path. On the native path, MCPClient._retry_operation treats the RuntimeError as retryable, sends tools/call up to MCP_MAX_RETRIES = 3 times with backoff, then raises ConnectionError(f"Operation failed after {self.max_retries} attempts: {last_error}"), and MCPNativeTool._run wraps it as Error executing MCP tool {name}: .... The executor renders the exception. _execute_single_native_tool_call in crewai/src/crewai/agents/agent_executor.py sets result = f"Error executing tool: {e}", and the ReAct path in crewai/src/crewai/tools/tool_usage.py uses the tool_usage_exception template, “I encountered an error while trying to use the tool. This was the error: {error}.” Both contain the SDK sentence. On the HTTPS path the error is raised inside the streamablehttp_client task group, and anyio 4.14.2 (uv.lock) raises BaseExceptionGroup("unhandled errors in a TaskGroup", ...) from None. _execute_tool matches "unhandled errors" in str(e) and raises asyncio.TimeoutError(f"MCP connection error: {e}"). _execute_single_attempt maps any asyncio.TimeoutError to f"Connection timed out after {MCP_TOOL_EXECUTION_TIMEOUT} seconds" with retry set. After three attempts the tool returns “MCP tool execution failed after 3 attempts: Connection timed out after 60 seconds” as a normal result, and the SDK sentence is lost. On the adapter path the RuntimeError propagates from _sync_call_tool through CrewAIMCPTool._run, and the executor renders it as on the native path.

Other paths: hooks, events, cache and a hand-rolled Merge client

execute_single_native_tool_call runs run_after_tool_call_hooks (crewai/src/crewai/hooks/tool_hooks.py) with tool_result=result and raw_tool_result, and the hook’s returned context.tool_result replaces what the model sees. For MCP tools both values are the extracted string, except that raw_tool_result is the ToolFailure holding it on an isError result, so hooks never see the CallToolResult. MCPClient.call_tool_result emits MCPToolExecutionCompletedEvent(result=tool_result.content) or MCPToolExecutionFailedEvent on crewai_event_bus, also carrying the string. The tools handler cache stores the same string and skips a ToolFailure. No code mode or sandbox route exists, and no crewAI code reads _meta on a tool definition or a result. The sandbox tools in crewai-tools/src/crewai_tools/tools/daytona_sandbox_tool/, crewai-tools/src/crewai_tools/tools/e2b_sandbox_tool/ and crewai-tools/src/crewai_tools/aws/bedrock/code_interpreter/ are ordinary tools, and none of their files mention mcp. No crewAI code renders an MCP Apps view or reads _meta.ui.visibility: under lib/, ui://, resourceUri and text/html;profile=mcp-app have no hits, and visibility appears only in unrelated code (crewai/src/crewai/a2a/extensions/a2ui/, crewai/src/crewai/flow/conversational.py, crewai/src/crewai/flow/conversational_mixin.py, cli/src/crewai_cli/skills/main.py, crewai-core/src/crewai_core/platform_catalog.py). No switch changes which field reaches the model. MCPServerStdio, MCPServerHTTP and MCPServerSSE in crewai/src/crewai/mcp/config.py carry connection settings, tool_filter and cache_tools_list, and MCPServerAdapter.__init__ takes server parameters, tool names and connect_timeout.

MergeAgentHandlerTool in crewai-tools/src/crewai_tools/tools/merge_agent_handler_tool/merge_agent_handler_tool.py is a separate JSON-RPC client over requests.post for the Merge Agent Handler service. _make_mcp_request sends tools/call with no initialize. _run returns json.loads(text_content) of content[0].get("text", ""), or the raw text when it is not JSON, when content is non-empty. Otherwise it returns the whole JSON-RPC response dict, which the executor renders with str(), including any structuredContent.

Protocol revision: whatever SDK 1.30.0 requests

crewAI pins no protocol string. MCPClient.connect, MCPToolWrapper._execute_tool and MCPToolResolver._discover_mcp_tools all call ClientSession.initialize(), which sends protocolVersion=types.LATEST_PROTOCOL_VERSION, "2025-11-25" in mcp/types.py. It fails with Unsupported protocol version from the server unless the reply is in SUPPORTED_PROTOCOL_VERSIONS (mcp/shared/version.py): 2024-11-05, 2025-03-26, 2025-06-18 and 2025-11-25. mcpadapt calls the same initialize() in mcptools. The Merge client sends no version.

Upstream history: the content flattener, no record on structuredContent

content_blocks_to_text came in through crewAIInc/crewAI#8300, merged 2026-10-23, fixing issue #8299, which reported that the native and HTTPS paths passed only result.content[0] to the agent. The PR body: "MCP tool results reached the agent with only result.content[0]. The rest of the blocks were dropped, and a non-text first block arrived as its pydantic repr with base64 data." It applied the helper in MCPClient._call_tool_impl, MCPToolWrapper._execute_tool and MCPNativeTool._extract_content, and left MCPServerAdapter unchanged: “It keeps all text blocks but returns them as a Python list repr, so the two integrations still format results differently.” The only human review is an approval with the body “lgtm”. An earlier attempt on the MCPClient copy, #5226, was closed unmerged on 2026-09-17.

The first-block logic and the return str(result) fallback for empty content are present in the first versions of both files on main: crewai/src/crewai/tools/mcp_tool_wrapper.py at #3618 (Release/v1.0.0, merged 2025-10-20) and crewai/src/crewai/mcp/client.py at #3850 (“Lorenze/feat mcp first class support”, merged 2025-11-07). Both PR bodies are empty, and #3850 has no comments and two reviews with empty bodies. The commits API returns no history for the pre-monorepo path src/crewai/tools/mcp_tool_wrapper.py at tags 0.201.1, 0.203.0 and 0.203.1. CrewAIToolAdapter in crewai-tools/src/crewai_tools/adapters/mcp_adapter.py came in through #4359, merged 2026-02-04, whose body is “fixes #4312”, a schema $ref error. mcpadapt’s own CrewAIAdapter in mcpadapt/crewai_adapter.py (0.1.19 and 0.1.20) has the same single-block and list-repr branches and tests hasattr(content, "text").

No record discusses structuredContent. GitHub searches of crewAIInc/crewAI issues and PRs for structuredContent, structured_content, outputSchema, structured content MCP and structuredContent mcp, and of crewAIInc/crewAI-tools for structuredContent, return nothing relevant. The clone is shallow at one commit, so git log and git blame reach no history, and the file histories above come from the GitHub commits API.

Quirks

The SDK types structuredContent as dict[str, Any] | None (mcp/types.py), so an array or scalar structuredContent fails model_validate in BaseSession.send_request on all three paths, while null parses as None.

An oversized successful result does not reach the model inline on the native tool-calling loop. AgentExecutor._prepare_tool_result_for_context (crewai/src/crewai/agents/agent_executor.py) runs when use_better_compaction is on, the default in crewai/src/crewai/agent/core.py, and defers any result that is_tool_result_overflowing_threshold (crewai/src/crewai/llms/base_llm.py) counts above TOOL_RESULT_CONTEXT_WINDOW_THRESHOLD = 0.25 of get_context_window_size(), skipping a ToolFailure. The extracted string goes to a temporary file through ToolResultArtifactStore (crewai/src/crewai/utilities/tool_result_artifacts.py), and the model gets a reference with the first 10 lines, capped at 2,000 characters, plus the DeferredToolResultReader tool (crewai/src/crewai/tools/agent_tools/deferred_tool_result_reader.py, named “Read a deferred tool result”) to read it in sections. The usable window is 85% of the model’s window, and the OpenAI provider (crewai/src/crewai/llms/providers/openai/completion.py) assumes DEFAULT_CONTEXT_WINDOW_SIZE = 8192 (crewai/src/crewai/llms/context_window.py) for a model missing from its catalog with no context_window_size set, so the threshold for such a model is about 1,740 tokens.
