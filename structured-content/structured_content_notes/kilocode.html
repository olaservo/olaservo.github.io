Ola’s MCP Tool Result Research

How kilocode handles MCP tool results

which mcp tool result fields are used and how (clients)

Notes from reading the kilocode source (clones/kilocode, checked out at commit 85eb887, read 2026-11-14). File references are relative to packages/opencode/src/ unless they start with packages/ or patches/.

Entry: TypeScript SDK 1.32.1 with a local patch, CallToolResultSchema keeps structuredContent

packages/opencode/package.json pins "@modelcontextprotocol/sdk": "1.32.1". patches/@modelcontextprotocol%2Fsdk@1.32.1.patch edits the installed SDK: it adds OAuth scope selection, session recovery on expiry, an isRequestActive callback on transport sends, and a reset argument on cacheToolMetadata so paginated listTools calls keep validators from earlier pages. It also adds typed callTool overloads to client/index.d.ts that return the passed schema’s output type. The patch leaves callTool result handling untouched.

mcp/index.ts builds one Client per server in createClient with new Client({ name: "kilo", version: InstallationVersion }, CLIENT_OPTIONS). CLIENT_OPTIONS declares only roots: {}; sampling, elicitation and tasks are commented out with upstream issue links.

Results enter in mcp/catalog.ts convertTool, which calls client.callTool({ name, arguments }, CallToolResultSchema, {...}). CallToolResultSchema in the SDK declares content: z.array(ContentBlockSchema).default([]) and structuredContent: z.record(z.string(), z.unknown()).optional(), so the parsed result keeps both fields.

The clone has no node_modules. CallToolResultSchema and LATEST_PROTOCOL_VERSION were checked against src/types.ts at tag 1.32.1 in modelcontextprotocol/typescript-sdk. A result with no content key parses to content: [] through the schema default, so it takes the structuredContent fallback in convertTool when structuredContent is present.

Model path: content wins, structuredContent fills in only when content is empty

convertTool throws when result.isError is set, joining the text blocks as the error message. Otherwise it applies one rule: if (result.content.length > 0 || result.structuredContent === undefined || result.structuredContent === null) return result. When both fields are present, the result passes through unchanged and structuredContent is never read again on this path. When content is empty and structuredContent is an object, the function returns a copy whose content is [{ type: "text", text: JSON.stringify(result.structuredContent) }]. A result with only structuredContent therefore reaches the model as one single-line JSON text block.

session/tools.ts wraps each converted tool. After execute returns it loops over result.content: text blocks go into textParts; image blocks become attachments entries with a data: URL; resource blocks contribute resource.text to textParts and resource.blob to attachments when the MIME type is in SUPPORTED_MCP_RESOURCE_ATTACHMENT_MIMES and the size is under MAX_MCP_RESOURCE_BLOB_BYTES (10 MiB), with a [Binary MCP resource omitted: ...] text line otherwise. audio and resource_link blocks match no branch and are dropped. The text parts are joined with "\n\n" and passed through truncate.output, whose defaults in tool/truncate.ts are MAX_LINES = 2000 and MAX_BYTES = 50 * 1024, overridable by the tool_output config block in packages/core/src/config.ts. The head loop breaks on the first line that would exceed the byte budget, so a stringified structuredContent larger than 50 KB contributes no bytes and the model gets a pointer to the spill file.

The wrapper returns { title: "", metadata, output: truncated.content, attachments, content: result.content }. session/processor.ts toolResultOutput reads only title, metadata, output and attachments from that object, and completeToolCall stores those four, so the raw content array is not persisted. session/message-v2.ts rebuilds the model message from the stored part: toModelOutput emits the output string as a text part and each data: attachment as a media part, with media moved to a separate user message when supportsMediaInToolResult is false for the provider. session/processor.ts resizes image attachments before storing them, and an image that cannot be resized below the limit is dropped and the stored output gains [N image(s) omitted: could not be resized below the image size limit.].

When both fields are present, the model gets the content text whether or not it mirrors structuredContent, so a mirrored payload appears once and there is no deduplication step. The rule tests only result.content.length, so a content array holding only an image, audio or resource_link block also suppresses the fallback. In that case the image reaches the model as an attachment, audio and resource_link are dropped as above, and structuredContent is not sent. No placeholder is substituted for an empty result. With content: [] and no structuredContent, textParts is empty, output is the empty string, and toModelOutput emits it as { type: "text", value: "" }. The transforms in provider/transform.ts that drop empty parts for @ai-sdk/anthropic and for Claude on Bedrock filter only text and reasoning parts and keep tool-result parts. The one fixed string on this path is "MCP tool returned an error", which convertTool throws when an isError result has no non-blank text block.

The flattening loop in session/tools.ts does not read annotations, so a block annotated audience: ["user"] reaches the model like any other block. A grep for audience in .ts and .tsx files under packages/ finds it only in acp/content.ts and its tests under packages/opencode/test/acp/. There audienceFlags maps an ACP prompt text block with ["user"] to an ignored part and one with ["assistant"] to a synthetic part. That file handles ACP prompt input and replay, not MCP tool results.

outputSchema: SDK validates, client code strips it on schema errors

mcp/catalog.ts listTools calls client.listTools, which in SDK 1.32.1 runs cacheToolMetadata and compiles an Ajv validator for every tool with an outputSchema. On a later callTool the SDK throws McpError when a tool with a cached validator returns no structuredContent on a result without isError (Tool ${params.name} has an output schema but did not return structured content), when the payload fails the schema (Structured content does not match the tool's output schema), or when the validator itself fails (Failed to validate structured content: ...); an isError result without structuredContent passes the SDK and reaches kilocode’s own isError throw. convertTool does not catch these, so the error surfaces as a failed tool call. session/processor.ts failToolCall stores errorMessage(error), the error’s message, as the part’s error, and session/message-v2.ts replays it to the model as the errorText of an output-error tool part.

If client.listTools throws and isOutputSchemaValidationError matches the message (/can't resolve reference|resolves to more than one schema|outputSchema|schema.*reference|reference.*schema/i), listTools re-requests that page with TolerantListToolsResultSchema, defined as ToolSchema.omit({ outputSchema: true }). That request goes through client.request directly, so no validators are cached for the failing tool or any tool after it on that page; cacheToolMetadata compiles eagerly in a loop, so tools earlier on the page keep their validators, and the patched cacheToolMetadata(tools, reset) clears the cache only when params?.cursor === undefined.

On the conversational path convertTool builds the AI SDK tool from description and inputSchema only; outputSchema does not appear in any prompt text.

Other paths: code mode returns structuredContent as a value, MCP Apps forwards both fields

tool/code-mode.ts defines an execute tool that tool/registry.ts registers when KiloCodeMode.wanted is true (KILO_EXPERIMENTAL_CODE_MODE, the umbrella KILO_EXPERIMENTAL, or experimental.code_mode), and session/tools.ts then skips registering individual MCP tools, so with code mode on the conversation receives only the script’s return value, JSON.stringify'd, and never a direct MCP tool result. invokeChildTool calls client.callTool the same way as convertTool. projectMcpResult collects text blocks, pushes image, audio and blob resource blocks into attachments, renders resource_link as ${block.name}: ${block.uri}, and then returns result.structuredContent as the script-visible value whenever it is not undefined or null, otherwise the joined text. toolTree passes entry.tool.def.outputSchema as the sandbox tool output, which packages/codemode/src/tool-schema.ts outputTypeScript renders into the TypeScript signature the model sees; decodeOutput passes JSON Schema outputs through unvalidated.

kilocode/mcp/apps.ts serves the MCP Apps feature behind KILO_EXPERIMENTAL_MCP_APPS. McpApps.callTool is an HTTP handler behind /experimental/mcp/call-tool that calls client.callTool without a result schema and returns content, isError and structuredContent to the caller; it serves calls a widget makes itself, and no widget host exists in the repo (the endpoint’s only consumer is the generated SDK client under packages/sdk/js/src/v2/gen). For a call the model made, the stored tool part holds only output, metadata and attachments, so that call’s structuredContent is not available to a widget. McpApps.toolMetadata reads entry.def._meta.ui.resourceUri and attaches { mcpApp: { resourceUri, serverId } } to the tool part metadata; this changes what the UI preloads, not what the model receives.

plugin.trigger("tool.execute.after", ..., result) in session/tools.ts receives the full CallToolResult before flattening, and plugin/index.ts trigger passes the same object to each hook and returns it, so a plugin can rewrite content from structuredContent before the flattening loop reads it. metadata on the conversational path spreads ...result.metadata from the raw result, so a top-level metadata key sent by a server lands in the stored part metadata; _meta is not copied. Per-server config carries timeout (packages/core/src/config/mcp.ts) and type: "remote", which SandboxNetwork.remote tags for network policy; neither changes result routing.

No code reads _meta.ui.visibility. A grep for visibility under packages/opencode/src hits only TUI and CLI keymap code, prompt and tip text, a comment in cli/cmd/run/tool.ts, and kilocode/tool/ods.ts with its import in kilocode/tool/xlsx.ts, and MCP.tools in mcp/index.ts registers every listed tool, so a tool marked app-only is still offered to the model. No _meta key, per-server config field or constructor option changes which field reaches the model. Outside tests, structuredContent appears under packages/ only in mcp/catalog.ts, tool/code-mode.ts, kilocode/mcp/apps.ts and the generated packages/sdk/js/src/v2/gen/types.gen.ts. Turning on code mode is the one switch that changes the field: the script then receives structuredContent whenever it is set.

Protocol revision: SDK default, 2025-11-25

Kilocode pins no protocol revision of its own. The patched _initialize sends protocolVersion: types_js_1.LATEST_PROTOCOL_VERSION, which is '2025-11-25' in SDK 1.32.1, and accepts any of SUPPORTED_PROTOCOL_VERSIONS back. cli/cmd/mcp.ts sends the same LATEST_PROTOCOL_VERSION in its debug initialize probe.

Upstream history: opencode added the fallback, then made content win

The rule in mcp/catalog.ts convertTool comes from upstream opencode and reached kilocode through upstream merges. The clone is shallow and git blame attributes every line to 85eb887, so the history below is from GitHub. anomalyco/opencode#32074, “fix(opencode): expose structured MCP output”, merged 2026-06-12, made convertTool replace content with JSON.stringify(result.structuredContent) whenever structuredContent was not undefined or null. Its body says: "This matches Codex behavior and allows tools that return only structuredContent, such as Qt Creator MCP tools, to provide visible results to the model." It closed #27263, a report that the Qt Creator MCP server sends "content":[] with the payload in structuredContent. Kilocode took it in Kilo-Org/kilocode#12404, “OpenCode v1.17.5”, merged 2026-07-22.

anomalyco/opencode#32832, “MCP tool can no longer return image attachments”, reported that a result with one image block and structuredContent: { "ok": true } lost the image from 1.17.5. rekram1-node, the author of #32074, closed it on 2026-06-22 with: “This isn’t a bug because the MCP spec does not require clients to merge content with structuredContent or preserve both in model context; preferring the stringified structuredContent is valid. It also matches the behavior of Claude Code and Codex, so preserving images alongside it would be unexpected, if u have an mcp server that is common that has this behavior plz let me know so we can look into it further, otherwise closing as wont fix since this is expected behavior”. #34505, “fix(mcp): prefer content over structured output”, also by rekram1-node and merged 2026-06-29, added the result.content.length > 0 condition. Its body lists “Preserve MCP content when structuredContent is also returned” and “Only fall back to structuredContent when content is empty”, links no issue, and records no rationale beyond that. Kilocode took it in Kilo-Org/kilocode#12695, “Opencode Merge v1.17.10-v1.17.13”, merged 2026-08-04.

anomalyco/opencode#38923 reported that with both fields present only the content text reaches the model, and a commenter traced the behaviour to #34505. It was closed as not planned on 2026-10-22 with: "This was traced to V1 code (packages/opencode/src/mcp/catalog.ts), which isn’t part of OpenCode 2.0. V1 now only gets critical fixes, and this isn’t one." #43123, which appended the stringified structuredContent after the existing content, was closed unmerged on 2026-09-17 by an automated cleanup of old PRs. In kilocode, Kilo-Org/kilocode#11695, “feat(cli): preserve mcp structured content”, which validated structuredContent and stored it on tool parts and SDK events, was closed unmerged on 2026-07-01 with no recorded reason.

Searched: gh search prs structuredContent and gh search issues structuredContent in Kilo-Org/kilocode and anomalyco/opencode, the bodies and comments of the PRs and issues above, and gh api repos/Kilo-Org/kilocode/commits/<sha>/pulls for the merge commits of #32074 and #34505.

Quirks

CallToolResultSchema declares structuredContent as z.record(z.string(), z.unknown()).optional(), so an array, a scalar or null fails result parsing in the SDK and the call surfaces as a failed tool call. After parsing, result.structuredContent is never null, so the null check in convertTool does not change any outcome. structuredContent: {} with content: [] reaches the model as the text {}.

When the shared agent board is on (the default; shared_agent_board: false or KILO_EXPERIMENTAL_SHARED_AGENT_BOARD set to false turns it off), finish in session/tools.ts runs every tool output, MCP results included, through BoardContext.notifier, which can set shared_agent_board_notice in the part metadata. On replay session/message-v2.ts calls BoardNotice.output, which appends a <shared-agent-board-notice> paragraph after the stored output text, so the model-facing text of an MCP result can carry this client-added notice.
