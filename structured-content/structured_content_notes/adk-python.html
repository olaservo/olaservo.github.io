Ola’s MCP Tool Result Research

How adk-python handles MCP tool results

which mcp tool result fields are used and how (clients)

Notes from reading the Google ADK Python source (clones/adk-python, checked out at commit 287c0b0e65899b0060efd5672c8f419c1119530d (287c0b0), read on 2026-11-14). File references are relative to src/google/adk/ unless they name pyproject.toml, tests/ or an SDK file. SDK references are to clones/python-sdk at commit 77001c9 (the 2.x line). pyproject.toml declares "mcp>=1.24,<3" in the mcp, all and test extras and not in the core dependencies. The repository has no lockfile. The uv pip compile --all-extras outputs constraints-3.11.txt through constraints-3.14.txt pin mcp==1.28.1, and constraints-3.15.txt pins mcp==2.3.0.

Entry: results enter through the SDK ClientSession, then become a plain dict

dependencies/_mcp.py imports ClientSession from mcp and sets IS_MCP_SDK_V2 by trying the 2.x import paths first. tools/mcp_tool/session_context.py constructs ClientSession(...) for each connection, and tools/mcp_tool/mcp_toolset.py McpToolset.get_tools wraps each entry of session.list_tools() in an McpTool. tools/mcp_tool/mcp_tool.py McpTool._run_async_impl calls McpTool._call_tool_on_session, which calls session.call_tool(self._mcp_tool.name, arguments=args, progress_callback=resolved_callback, meta=meta_trace_context) and receives the SDK’s CallToolResult. It then converts the model with result = _dump_mcp_model(response). On 1.x that is model.model_dump(exclude_none=True, mode="json"). On 2.x it is model.model_dump(exclude_none=True, mode="json", by_alias=True) followed by _restore_meta_keys, which renames _meta to meta and does not descend into the structuredContent, inputSchema, outputSchema and _meta values (_OPAQUE_KEYS). On 2.x result.pop("resultType", None) removes the result-type field. The returned value is a dict with the keys content, structuredContent, isError and meta as the server sent them. exclude_none drops only None, so content: [] and isError: false survive. tests/unittests/tools/mcp_tool/test_mcp_tool.py test_structured_content_keeps_its_camel_case_key asserts result["structuredContent"] == {"answer": 42}. Outside the dump helper, no code under src/google/adk/ names structuredContent, and no MCP-specific code reads content. In clones/python-sdk src/mcp-types/mcp_types/_types.py, CallToolResult declares content: list[ContentBlock] with no default, and InputRequiredResult._require_one_field rejects a result with neither input_requests nor request_state. src/mcp/client/session.py parses tools/call responses with TypeAdapter(types.CallToolResult | types.InputRequiredResult), so a result without a content key fails to parse in the SDK before ADK sees it. Before that adapter runs, ClientSession.send_request calls _methods.validate_server_result(method, version, raw) against the negotiated revision’s wire model, which src/mcp-types/mcp_types/methods.py lists as v2025.CallToolResult for 2025-11-25 and v2026.AnyCallToolResult (CallToolResult | InputRequiredResult) for 2026-07-28, so the pydantic.ValidationError names CallToolResult alone on a handshake session and the two-arm union on a modern one. ADK does not catch it in _call_tool_on_session or _run_async_impl, so it reaches McpTool.run_async and takes the path described under outputSchema below: with graceful error handling on (the default) the model receives only {"error": "Unexpected error during MCP tool execution: <validation error>"}, and with ADK_DISABLE_MCP_GRACEFUL_ERROR_HANDLING=1 the exception reaches _caller.py and no tool result reaches the model unless an on-tool-error callback returns one.

Model path: the whole dict on Gemini, content first on Anthropic

flows/llm_flows/tools/_caller.py _build_response_event runs _extract_multimodal_parts, which pulls out only types.Part instances, so an MCP dump passes through unchanged. _build_function_response_content then calls types.Part.from_function_response(name=tool.name, response=cast(dict[str, Any], _unwrap_enums(function_result)), parts=function_response_parts) with the whole dict as response. What reaches the model depends on the backend converter under models/:

  • google_llm.py (Gemini API and Vertex) sends the FunctionResponse as built, so the model receives the entire dict with both content and structuredContent.
  • interactions_utils.py passes part.function_response.response through unserialized as the function_result result.
  • lite_llm.py sends _safe_json_serialize(response), which is json.dumps(obj, ensure_ascii=False), as the tool message content.
  • apigee_llm.py sends 'content': json.dumps(part.function_response.response).
  • anthropic_llm.py _part_to_message_block reads response_data["content"] when it is a non-empty list. Each text item contributes its text, every other item contributes str(item), and the pieces are joined with "\n". When content is empty or missing, the fallback branch sends content = json.dumps(response_data), the whole dict. The ToolResultBlockParam carries is_error=True when the dict has a truthy isError or is_error, and is_error=False otherwise.

With both fields present, the Gemini, Interactions, LiteLLM and Apigee paths deliver both, and the Anthropic path delivers the content text and drops structuredContent. With content: [] and structuredContent present, every path delivers the dict, and on Anthropic that is the JSON string of the dict including "content": []. Image, audio and embedded-resource blocks stay dicts inside content and are never converted to FunctionResponsePart media. On Gemini, Interactions, LiteLLM and Apigee they reach the model as JSON with inline base64 data. On Anthropic they reach it as the Python str() of the block dict. An isError: true result takes the same path, with the flag as one key of the dict. On Anthropic and Interactions it also sets is_error on the tool result. No code compares the content text with structuredContent, so a text block that mirrors the JSON reaches the Gemini, Interactions, LiteLLM and Apigee paths alongside it (a grep for structuredContent under src/google/adk/ finds only _OPAQUE_KEYS and the _dump_mcp_model docstring in tools/mcp_tool/mcp_tool.py). On Gemini and Interactions, structuredContent is a JSON value inside the dumped result dict. On LiteLLM, Apigee and the Anthropic fallback it is part of one json.dumps string of the whole dict, with the default ", " and ": " separators and no indentation. ADK substitutes no placeholder for an empty MCP result. A result with content: [] and no structuredContent still dumps to a dict with content and isError, so it takes the same paths as above. The anthropic_llm.py branch that leaves content = "" runs only for an empty dict, which an MCP dump never is.

No file under src/google/adk/ reads audience on the model path. A grep for audience returns only auth/, cli/ (api_server.py, cli_deploy.py, cli_tools_click.py, deployers/_dockerfile_template.py, fast_api.py, trigger_routes.py), integrations/eventarc/_client.py and tools/openapi_tool/auth/credential_exchangers/service_account_exchanger.py, all of them OAuth or OIDC audiences. The dump keeps each block’s annotations as a key of the block dict, so a block with audience: ["user"] reaches the Gemini, Interactions, LiteLLM and Apigee paths with its annotations in the JSON. On Anthropic a ["user"] text block contributes its text, and a ["user"] non-text block contributes its str() with the annotations in it.

outputSchema: validated by the SDK, also forwarded to the model as a schema

McpTool._build_declaration reads the schema when is_feature_enabled(FeatureName.JSON_SCHEMA_FOR_FUNC_DECL) is true: output_schema = _read_field(self._mcp_tool, "outputSchema", "output_schema"), then FunctionDeclaration(name=..., description=..., parameters_json_schema=input_schema, response_json_schema=output_schema). features/_feature_registry.py registers that flag as FeatureConfig(FeatureStage.STABLE, default_on=True). When the declaration goes to the model, McpTool.process_llm_request replaces it with _build_fenced_declaration(), which runs fence_schema_descriptions (flows/llm_flows/context/_fencing.py) over the input and output schemas, so every description string inside the forwarded schema is wrapped in <<<BEGIN_UNTRUSTED_TOOL_DESCRIPTION>>> markers. google_llm.py sends the declaration as built, so Gemini receives the schema as response_json_schema. lite_llm.py _append_response_schema_to_description renders it into the tool description as f"Returns {type_label} conforming to this schema: {rendered_schema}", and leaves it out when the result would exceed _MAX_TOOL_DESCRIPTION_LENGTH (1024 characters) or the schema has no key besides type. anthropic_llm.py function_declaration_to_tool_param and interactions_utils.py convert_tools_config_to_interactions_format copy only name, description and parameters, so those backends drop it. ADK does not use the schema to choose which field to send.

Validation happens in the SDK. In clones/python-sdk src/mcp/client/session.py, ClientSession.call_tool runs if isinstance(result, types.CallToolResult) and not result.is_error: await self.validate_tool_result(name, result). validate_tool_result re-lists tools when the name is not cached and raises RuntimeError(f"Tool {name} has an output schema but did not return structured content") or RuntimeError(f"Invalid structured content returned by tool {name}: {error}"). The 1.x SDK was not read for these notes. ADK runs no validation of its own.

McpTool.run_async catches the exception when is_feature_enabled(FeatureName._MCP_GRACEFUL_ERROR_HANDLING) is true. The registry sets that flag as default_on=True, and ADK_DISABLE_MCP_GRACEFUL_ERROR_HANDLING=1 turns it off. The comment above the _to_gemini_schema import in tools/mcp_tool/mcp_tool.py says the flag is off by default, which the registry contradicts. A RuntimeError is not an McpError, so it lands in except Exception as e and the tool returns {"error": f"Unexpected error during MCP tool execution: {e}"}. The model sees that one key and nothing from the original result. On Interactions the error key also sets is_error on the tool result. With the flag off, the exception reaches _caller.py _execute_single_prepared_call, which runs run_on_tool_error_callbacks and re-raises when no callback returns a response.

Other paths: callbacks, telemetry, grounding metadata, MCP Apps widgets

_caller.py _execute_single_prepared_call hands the dict to the plugin run_after_tool_callback(..., result=callback_tool_response) and then to the agent’s canonical_after_tool_callbacks with tool_response=callback_tool_response. A non-None return replaces the dict before the FunctionResponse is built. Before-tool and on-tool-error callbacks can also supply the response. flows/llm_flows/tools/_error_handler.py detect_error_type_for_telemetry calls McpTool._detect_error_in_response, which returns "MCP_TOOL_ERROR" when response.get("isError") or response.get("is_error"), and records it as the span error type without changing the response. telemetry/tracing.py writes function_response.response to the span as gcp.vertex.agent.tool_response or GEN_AI_TOOL_CALL_RESULT when content capture is enabled, so the full dict, structuredContent included, goes to telemetry. It passes through _serialize_tool_response, which masks credential-typed values and, via _redact_credential_secrets at any depth, credential-shaped dicts (for example an authType with an auth-type value, rawAuthCredential or exchangedAuthCredential keys, requestedAuthConfigs), so such a dict inside structuredContent reaches the span with its secret keys stripped.

Two _meta readers exist. McpTool._store_grounding_metadata_from_result copies meta.adk_grounding_metadata from the result into temp:_adk_grounding_metadata when propagate_grounding_metadata is set, and flows/llm_flows/core/_finalizer.py attaches it to the LlmResponse as grounding_metadata. When the tool definition has meta.ui.resourceUri (or the flat ui/resourceUri) starting with ui://, _run_async_impl calls tool_context.render_ui_widget(UiWidget(..., provider="mcp", payload={"resource_uri": ..., "tool": ..., "tool_args": args})). That payload carries the tool definition and arguments, not the result. The McpTool.visibility property reads meta.ui.visibility and has no caller, so an app-only tool is still offered to the model. No code-mode or scripting path calls MCP tools. No McpToolset.__init__ or McpTool.__init__ argument in tools/mcp_tool/mcp_toolset.py and tools/mcp_tool/mcp_tool.py, and no _meta key, changes which field the model gets. Which field reaches the model depends on the model backend and on any callback that replaces the dict.

Protocol revision: the SDK handshake by default, the modern probe behind a flag

ADK pins no protocol string. tools/mcp_tool/session_context.py _connect runs await session.initialize() unless FeatureName._MCP_MODERN_PROTOCOL is enabled, which the registry sets as FeatureStage.EXPERIMENTAL, default_on=False. On 2.x initialize offers LATEST_HANDSHAKE_VERSION, which is "2025-11-25" in clones/python-sdk src/mcp-types/mcp_types/version.py. With ADK_ENABLE_MCP_MODERN_PROTOCOL=1 on 2.x, _connect calls negotiate_auto (imported from mcp.client._probe in dependencies/_mcp.py), which probes server/discover with LATEST_MODERN_VERSION ("2026-07-28") and falls back to the handshake. On 1.x negotiate_auto is None and the handshake runs.

Upstream history: the whole-dict dump and the Anthropic content branch

The content branch in anthropic_llm.py _part_to_message_block was added by commit 1dd97f5b on 2025-11-17, an internal change with no pull request and no message body. The whole-dict dump came from commit 4df92638, whose message says the aim was that “what ADK runtime sees is identical to what is persisted in the session event list”. No issue or pull request in the repository discusses the Anthropic path dropping structuredContent. Issue #7073 raised the same Gemini-versus-Claude gap for dicts with a result key and left the MCP content branch out of scope on purpose.

Quirks

_dump_mcp_model in tools/mcp_tool/mcp_tool.py dumps with exclude_none=True, so a structuredContent: null from the server is dropped and the dict looks the same as one with no structuredContent.

On a handshake session the SDK checks the result against the 2025-11-25 wire model in clones/python-sdk src/mcp-types/mcp_types/_v2025_11_25/__init__.py, whose structured_content is dict[str, Any] | None, so a string, number or array structuredContent fails validation and the model receives the graceful-error dict in place of the result. At 2026-07-28 (ADK_ENABLE_MCP_MODERN_PROTOCOL=1 on 2.x) the wire model in _v2026_07_28/__init__.py and CallToolResult in _types.py both type it as Any, so a non-object value passes and reaches the model inside the dumped dict.
