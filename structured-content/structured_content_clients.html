Ola’s MCP Tool Result Research

An MCP tool result has two payload fields. What happens to them in twenty agent clients?

which mcp tool result fields are used and how (clients)

Two fields, no stated audience

A tool result carries content, a required array of typed blocks (text, image, audio, resource), and optionally structuredContent, any JSON value, which must match the tool’s outputSchema when one is declared. The specification recommends that a server returning structuredContent also put the same JSON in a text block in content.

One result can have several consumers: the model’s context, a script the model wrote, an MCP App view, and hooks or plugins. The protocol’s only audience signal is the audience annotation on individual content blocks. It is advisory, and structuredContent has no equivalent annotation. This means that a server author can’t tell from the result alone which consumer will read which field. The essay Humans are still the users covers why that matters for what gets shown to people.

This page shows what twenty client implementations in nineteen open source repositories do with three example results, read from their source. Each client links to its note, which has the file paths, the quoted source and the commit it was read at.

Every row describes a default installation at the linked commit, read from source against a fixed checklist and not run. Opt-in routes are marked. A live probe ran six of these implementations (codex, goose, mastra, fx, libfx and the TypeScript SDK client) against fixture results on 2026-11-07, at that day’s commits. The pins on this page have since moved for codex, goose, mastra and fx. Every default-configuration observation agreed with the notes.

If you send a summary and the data

This is the MCP Apps pattern: a short text for the model and the full data for the view.

{
  "content": [{ "type": "text", "text": "Found 3 open issues" }],
  "structuredContent": { "issues": [ ... ] }
}
The model readsClients
[…] the summary only zed, goose, strands, crewAI, deepagents, LibreChat, kilocode, pi
{…} the data only codex, VS Code, agent-framework (Python), eve
[…] and {…} hermes-agent, as {"result": <summary>, "structuredContent": <data>}
⟨…⟩ the whole envelope cline, agent-framework (.NET), fx
it depends mastra on whether the tool declares an outputSchema (summary with one, data without). adk-python on the model backend (envelope on Gemini, summary on Anthropic). opencode routes MCP tools through a script by default, so the model reads whatever the script returns. fast-agent does the same for six catalog models, and reads the data for the rest.

If you mirror the data as text

This follows the specification’s recommendation: the text block is an exact JSON copy of structuredContent.

{
  "content": [{ "type": "text", "text": "{\"issues\":[ ... ]}" }],
  "structuredContent": { "issues": [ ... ] }
}
The model reads the payloadClients
once, from the text zed, goose, strands, crewAI, deepagents, LibreChat, kilocode, pi, mastra with an outputSchema, adk-python on Anthropic
once, from structuredContent codex, VS Code, fast-agent, agent-framework (Python), eve, mastra without an outputSchema
once, after a duplicate check hermes-agent drops the structured copy when a text block parses to an equal value. fx’s libfx adapter drops the text when it is byte-identical to the compact JSON.
twice cline, agent-framework (.NET), adk-python on Gemini, fx’s native engine

Only hermes-agent and libfx compare the fields. The others pick a field, or send both, without checking whether the two hold the same data.

In five clients the data never reaches the model for this result: zed, goose, LibreChat, strands and deepagents.

What scripts get

In programmatic tool calling, or code mode, the model writes a script that calls tools, and the script’s output is what enters the model’s context. The script needs a value it can use, and ideally its type before the script is written.

Six clients render outputSchema as a return type the model sees before it writes code: opencode, kilocode, mastra, codex and pi as TypeScript, and fast-agent as a Returns line in the stub. eve renders it as Promise<T> in tool search results, which have no script path.

Who can change the answer

The field the model reads is set in different places in different clients.

Set byWhatClients
server whether the tool declares an outputSchema mastra
server a non-text block in content eve, where the blocks then win over structuredContent
server a private _meta key codex (codex/encryptedContent), agent-framework .NET (any result _meta key forces the envelope)
server audience: ["user"] on a block goose, VS Code
server the size of the result fx (over the inline cap with no session store, only the text of content survives truncation; with a store, the model gets a 4 KiB preview of the envelope, which a long text mirror fills before structuredContent appears), VS Code (a text part over 8 KiB goes to disk and the model gets a pointer string), codex (a token budget truncates whichever payload was chosen), hermes-agent (over 50,000 characters the result goes to disk and the model gets a 1,500-character preview, in which structuredContent comes after the text)
host a constructor option agent-framework Python (tool_result_content: five modes)
host the model backend adk-python
host code mode on or off opencode, kilocode, mastra, fast-agent
host MCP Apps on or off LibreChat
model the script it writes every client with a script route

Most clients also run hooks or plugins that can rewrite the result before the model sees it. The notes list them.

Closed source clients

Claude Code, Claude Desktop, claude.ai, Cowork and Claude for Excel cannot be read, so a separate note records what public issue reports say, each as a reported observation with the client and version named, its issue state and its date. The repeated report is that structuredContent replaces content on the model path: anthropics/claude-code#103396 (open, 2026-10-19, labelled has repro, a server that puts query rows in content and a citation card in structuredContent) and anthropics/claude-ai-mcp#1201 (open, 2026-10-29, Claude Desktop 4.4 with an MCP App server, where the reporter says 3.6 sent content). Other reports cover MCP App views receiving no structuredContent, and requests to show outputSchema to the model and to honour audience, both closed as not planned. Nothing in that note was read from source.
