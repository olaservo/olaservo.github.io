limiting skills bloat · what a catalog looks like

How do harnesses bound their agent skills catalog?

Every host in this sample implements a baseline of:

  • name and description from the skill frontmatter gets injected into context
  • Most hosts below also include the file path for the SKILL.md in their catalog/manifest

Where they differ is what happens to the skills catalog itself as the number of installed skills grows. This is important to be aware of because similar to tools, loading too many skills up front can use up a lot of tokens and make your skills and tools trigger less reliably.

While many harnesses have some kind of optimization around how they load tools, it is still early days for skills and more generalized progressive discovery patterns haven't been standardized yet.

None of the sampled hosts ranks skills by relevance to the current task*. The budgeted hosts decide what stays in the catalog by size, not by fit.

The creature below represents an agent and its context window; each column shows one of the 3 approaches observed in this sample:

  • No enforced budget or limit for installed skills
  • Clipping skill descriptions to reduce token usage for each loaded skill
  • Setting a max budget for skills (e.g. a % of the context window, or a max character count) and laddering/ranking which skills get included in that budget

Disclaimer: this is just a sample of popular open source harnesses and not an exhaustive list. If you have an example you think should be included, feel free to reach out on LinkedIn.

what each approach does as the list grows

Drag each slider to simulate installing more skills. (Note that 'card counts' are just for illustration, the real budgets are measured in characters or tokens.) The bar and token counter under each creature show the catalog's total size, on the same scale in all three figures, assuming the worst case the spec allows per skill: a 64-char name and a 1024-char description, plus a file path — roughly 320 tokens per full entry. The wavy lines inside each creature are everything else in context — conversation, files, memory — which gets squeezed, and eventually compacted, as the catalog grows.

bonus: what a constructed catalog actually looks like

Rendered out, the catalogs from these harnesses fell into two syntax families: XML elements per skill (pi, opencode, fast-agent, openclaw) or one plain line per skill (codex, goose, hermes). Verbatim examples from each host, and the degraded forms under budget pressure, are on a companion page.
